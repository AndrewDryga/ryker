Connect Ryker to GitHub

Connect your repositories so Ryker can explain code, prepare changes, and follow a pull request through review.

Create and install the App

In GitHub’s account or organization settings, open Developer settings › GitHub Apps › New GitHub App. Follow GitHub’s registration guide for the form. Choose the permissions below, then install the App on the repositories you want Ryker to use.

Generate a private key. In Ryker, open Integrations › GitHub and enter the App ID and key. Copy the webhook URL and secret Ryker supplies into your App’s webhook settings, and keep webhooks active.

Choose the permissions

Repository permissionAccessUsed for
ContentsRead/writeRead code and publish task branches
IssuesRead/writeRead and reply to issues
Pull requestsRead/writeDrafts, comments and reviews
ChecksReadRead check results
Commit statusesReadRead commit status
ActionsRead; write for rerun/cancelInspect and manage workflow runs
MetadataReadRepository details

The App’s installation sets the outer limit of repository access. In Ryker, import the repositories under Work › Repositories, then choose which ones each environment can read or change under Work › Environments. Importing a repository alone does not give every conversation access to it.

Subscribe to events

Enable these event groups in the App’s settings:

  • Conversations: Issue comment, Issues, Pull request, Pull request review, and Pull request review comment.
  • CI: Check run, Check suite, Status, Workflow run, and Workflow job.
  • Repository changes: Repository.

Ryker retrieves App deliveries every 30 seconds, so GitHub does not need a direct connection to your host. For direct delivery, expose only /v1/github through HTTPS. See network access and the GitHub event reference.

Control draft pull requests

Opening pull requests is off until you enable it in the GitHub integration. After that, a confirmed task can open its draft when the person confirming it named the repository and the review is clean. Otherwise, a configured operator presses Create draft PR.

Ryker publishes the reviewed change on its own branch. If someone changes that branch outside Ryker, it will not overwrite their work. Your team reviews, marks ready and merges the pull request.

Follow a code change from Slack to GitHub for the complete walkthrough, or read the publication rules.

Ask for a review

Ask Ryker to review a connected pull request in Slack, GitHub or the console’s Chat. Include its URL and what you want examined. On GitHub, the person requesting work needs write or admin access to the repository.

Ryker can read the diff and discussion, leave inline comments, and request changes. Its review records the commit it examined. Approving pull requests is a separate repository setting, off by default. Ryker has no merge operation.

Comments on a pull request Ryker created return to the original task. If CI fails on its published commit, the task can resume, fix the issue within its scope, and update the same draft.

Check the connection

Ask a question about an imported repository from a conversation using its environment. Check that the reply cites actual files. Then use the code-change walkthrough to test draft publication if you have enabled it.

If a repository is missing, check the App’s installation, Ryker’s repository list, and the conversation’s environment. If follow-ups are missing, check the subscribed events, webhook secret, and App deliveries, then inspect the request in Activity and Failures.
