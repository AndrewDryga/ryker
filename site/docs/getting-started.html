Install Ryker

Run Ryker on your own host, connect your tools, and ask it a first question in Slack. The installer starts the services; the setup page walks you through the connections.

What you need

  • A trusted host with Git, Docker, Docker Compose v2, OpenSSL, curl and tar.
  • A model account. The installer signs in to Codex inside co:op’s private worker; it keeps that sign-in separate from any model account session on your host.
  • A Slack workspace where you can create and install an app.
  • A GitHub account that can create an App and install it on the repositories you choose.
  • Optionally, an Emisar account for access to running systems.

The first install builds its images locally. The included voice and search models add about 4 GB of images and use about 3.5 GB of memory, in addition to Ryker and its worker. Their first build downloads about 2.8 GB. See what runs on the host.

Install

git clone https://github.com/AndrewDryga/ryker ryker
cd ryker
./install.sh

The installer creates .ryker/, generates the database password and encryption keys, builds the images, and starts PostgreSQL, Ryker and the bundled worker. It asks you to sign in to the model account when the worker needs one.

When health, readiness and the running version check out, it prints a link that signs you in and opens setup. The link works once, within an hour. Running the installer again keeps your existing keys and data.

Open the printed link. If it expires, run this on the host for another:

scripts/compose.sh sign-in

Enter Slack, GitHub, Emisar and webhook credentials in Ryker’s setup pages. Ryker encrypts them in PostgreSQL. The owner-only .ryker/compose.env holds installation settings and generated encryption keys; keep it with your backups.

Set it up

Setup at http://127.0.0.1:4321/setup opens after you sign in. Follow these six steps:

  1. Connect Slack. Create an app from Ryker’s Slack manifest. Generate an app-level token with connections:write, install the app, and paste its app token and bot token into Ryker. Choose who can manage it.
  2. Connect GitHub. Create and install a GitHub App using the checklist below. Enter its App ID and private key in Ryker, then copy the webhook settings Ryker supplies into the App’s settings.
  3. Add repositories. Choose the repositories Ryker may use. It reads each one and keeps its reference notes under Work › Repositories, without opening a pull request or changing your files. Under Work › Environments, create an environment and choose its repositories and their read-only or read/write access.
  4. Invite Ryker. In your Slack channel, send /invite @Ryker. It posts a welcome message.
  5. Choose the channel’s environment. Select it under Work › Channels or press Customize on the welcome message. A channel uses the default environment if one was already chosen when it joined.
  6. Ask a real question. Use the example below with one of the repositories you added. Setup notices Ryker’s delivered reply and marks this step complete.

Connect Emisar under Integrations › Emisar when you want Ryker to investigate or act on running systems. It is optional. The first connected account is assigned to environments that have none; later accounts are assigned on the Environments page.

Create the GitHub App

In your GitHub account or organization settings, open Developer settings › GitHub Apps › New GitHub App. GitHub’s registration guide covers the form.

  • Repository permissions: Contents, Issues and Pull requests need read/write access for code changes and replies. Checks and Commit statuses need read access. Actions needs read access to inspect CI, or read/write if Ryker should rerun or cancel workflows. Metadata is read-only.
  • Events: subscribe to Issue comment, Issues, Pull request, Pull request review and Pull request review comment. Add Check run, Check suite, Status, Workflow run and Workflow job for CI follow-ups, plus Repository for repository changes. The GitHub adapter reference lists the full supported event set.
  • Install the App on the repositories Ryker should access. Generate a private key and keep the App ID for Ryker’s connection form.
  • Keep webhooks active. Use the Webhook URL and secret Ryker supplies. Ryker also retrieves the App’s deliveries every 30 seconds, so GitHub does not need a direct route to your host. To receive events directly, expose only /v1/github through HTTPS; see network access.

The App grants access to repositories; your environment then chooses which ones each conversation can use. Opening draft pull requests is a separate Ryker setting, off until you enable it.

Get your first answer

In the channel you configured, replace the repository name and send:

@Ryker what does your-team/your-repository do, and how do its tests run?

Ryker should answer in Slack using the repository’s actual files. Open Activity in the console to inspect that request’s timeline, the work it did, and its cost. You can also ask in Chat to test the same path without Slack.

For a service check on the host:

scripts/compose.sh status
curl --fail http://127.0.0.1:4321/healthz
curl --fail --include http://127.0.0.1:4321/readyz

/healthz checks the database connection. /readyz checks the runtimes and progress of due work; its x-ryker-version header identifies the running version. The Slack reply checks the full path from your question to a delivered answer.

If you get stuck

The console asks you to sign in
Use the installer’s link or run scripts/compose.sh sign-in. Slack operators can use /ryker sign-in. For a remote host, use an SSH tunnel or configure HTTPS access.
Ryker cannot see a repository
Check the App’s installation and Work › Repositories, then add that repository to the channel’s environment. Importing alone does not make it available to conversations.
No reply arrives in Slack
Check Integrations › Slack, confirm Ryker joined the channel, and mention it directly. In Activity, look for the request. If it is there, its timeline and the Failures page show where it stopped.
Work waits for a worker or model
Check Settings › Advanced and Work › Working copies. If the model account needs a new sign-in, run scripts/compose.sh model-login. Health and recovery covers service failures.

Choose what happens next

New channels start with mentions only unless you changed the installation default. Background learning is on by default. Proactive participation, draft pull requests and weekly reports are separate choices you can enable when you are ready.

Try Be proactive in one channel, ask for a scheduled check, or save a team decision. Changes to running systems follow the policy and approvals of the Emisar account you connected.
