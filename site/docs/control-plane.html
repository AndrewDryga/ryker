The control plane

Every episode has a full trace, and the trace is on a web UI served by the same binary, on the same host, over loopback. This is where “it shows its work” stops being a slogan and becomes a page you can open.

What it is

The control plane is served by the Responder process itself, from Go templates, with no build step. It is bound to loopback along with everything else. There are no accounts, no roles, and no invitations, because the loopback interface is the authentication. If you can reach it, you are already on the host.

Three properties are worth stating because they were chosen, not inherited:

  • No JavaScript at all. The content security policy has no script source. Every confirmation is a native two-step disclosure that posts a form; every chart is inline SVG computed on the server. A confirm dialog that needs a script is a confirm dialog that silently does nothing when the policy blocks it — which is exactly what happened once, and why this rule exists.
  • No external assets. No CDN fonts, no analytics, no telemetry. The page must render with the network off, and nothing about production work should leave the machine.
  • Nothing here mutates infrastructure. Emisar remains the only path. The control plane can retry work, keep a correction, publish a reviewed tree, or resolve a memory review. It cannot run an action.

Every write is a POST, attributed to the control plane as an actor, and its store transition and its audit row commit together.

Detail routes hang off these: one episode, one schedule, one incident, one failure, one conversation, one channel, one rule, plus preferences, assignments, and stored artifacts.

Filters and time windows are links, not controls. A filtered list stays a URL — bookmarkable, and pasteable into an incident thread — with no client state to keep in sync.

An episode trace

The episode page is the centre of the product. It is not a collection of reports; it is one execution story. A summary answers “how did it go?”, and a rail below it answers “what happened, in order, and why?” — cut into chapters a stranger can follow, with a time bar showing where the wall clock actually went.

The exact model input

The prompt is shown as it was submitted, grouped by what it was made of: the Slack conversation (the target message, the messages around it, any referenced thread, attachments, channel context), operational memory, conversation memory, related conversations, recalled past episodes, recent changes, and the workspace and prompt controls.

Every slot renders a row whether or not it was filled. That is the design. A layer that was included says why. A layer that was absent says why it was absent — and critically, a layer the budget cut is labelled as trimmed, never as “nothing was relevant”. Those are different facts and reading one as the other sends you debugging the wrong thing.

Each omission carries its own reason, in the words the host used at the time: earlier evidence records were omitted to fit the turn; related conversation summaries were omitted to fit the turn; the referenced transcript was cut back to fit the turn; operator-confirmed memory was omitted to fit the turn. A layer is reported the first time anything is taken from it, not when it reaches empty — a turn that dropped 389 of 400 channel messages and fitted at eleven used to say nothing at all, staying silent for precisely the prompts that lost the most.

Omissions do not travel forward. When a later attempt extends a manifest, a layer trimmed once would otherwise read as trimmed forever, including on the attempts that carried it in full.

Replay fingerprints

Two SHA-256 digests are recorded on every context manifest: a prompt replay fingerprint over the exact submitted bytes, and a context replay fingerprint over the assembled context. Alongside them the manifest freezes the prompt version, the contract version, the tool schema version, and the provider, model and reasoning effort that actually answered — after any ladder rotation, not the one that was requested.

The two-clock prompt

The submitted prompt is transport state and expires on the short operational horizon. A sanitized archive copy lives on the much longer episode horizon. Before that second copy existed, only 428 of 1221 manifests still held a prompt, and every one was from the previous two days — the harvest was never limited by a code path, it was limited to yesterday.

The trace prefers the submitted bytes. When only the archive remains it labels it Redacted archive and says in as many words that it will not hash to the fingerprint printed below it.

Refusals and corrections

When the host refuses a model answer, that refusal is a step on the rail like any other: “the result did not fit the required format, so Responder sent a correction back instead of acting on it.” The exact correction text is written to the audit log and shown here.

Four correction classes: unreadable, incomplete, rejected, and shape. The last is the only one that posts on a second attempt rather than blocking the turn — right content, wrong form.

Measurement, and the refusal to guess

Two habits run through every number on this UI.

Measured and zero are different. Usage and latency both carry an explicit “was this recorded?” flag, so nobody ever renders an unmeasured turn as free or instant — down to the trend, where a day of unmeasured attempts gets its own mark rather than a missing bar.

Wall clock is three spans, not one duration. Queued is Coop holding a turn before a provider picked it up. Provider is the provider working. Host is Responder not yet having noticed the turn finished, because it polls — that gap is real, is nobody else’s, and is the one span this codebase can fix on its own. Provider time is deliberately not split into inference and tool calls, because the underlying record does not hold that split, and an invented split in a latency report is a guess wearing a measurement’s clothes.

Cost follows the same rule. Provider-reported amounts are shown directly and never re-priced. An optional local price table fills in providers that report tokens but no money — and a model with no rate reports no estimate, never a zero that reads as “free”. Reported and estimated are printed on separate lines and never summed.

Panels that are not wired to anything say so, in a designed marker that states both why it is empty and what would fill it. It never renders a zero, and never an estimate dressed as a measurement.

The decisions queue

This is where the product improves on the record.

Every host refusal queues a fixture candidate — the host has already decided the model was wrong and said why, so the label is free. Candidates carry the episode, the run, the capability, the correction class and the correction text, and they expire after fourteen days if nobody looks.

You keep or discard each one, here or from App Home. A kept candidate is promoted into the regression corpus at testdata/eval/regressions.jsonl, inside whichever configured repository already contains that file — deliberately not a configurable path, which makes it impossible to point auto-promotion at the wrong tree.

Promotion runs on the maintenance lane, bounded to a small number per week, because the manual step is the one that stopped happening. Before anything is appended, the whole corpus is re-parsed with the new fixture in place; one that would not decode, or whose name is taken, is held in quarantine and surfaced here rather than retried into a corrupt file.

The result is the property the whole project rests on: a real production failure becomes a recorded real model answer that replays offline, with no credentials and no model call, on every commit.

The Decisions page also carries the watch decisions themselves — what Responder chose to do with each message, its attention scores, and the reason it recorded — plus correction rates, judged evaluation results, feedback, and the model audition panel.

Why the audition panel has two halves that never join

One half is live traffic: provider, model, effort, usage, corrections, cost. The other is recorded evaluation: gate-pass rate, judge mean, case count. Evaluation results record no provider and no model, and live traffic has no gate to pass. A grid keyed by both would be inventing an attribution neither source holds, so the two are shown side by side and left alone.

Findings

A finding is a proposed defect in Responder itself, not in your infrastructure. A read-only assessor reads terminal episodes out of process and proposes one; a second, independent read-only reviewer then tries to disprove it. Both verdicts are shown.

That challenger is not decoration. In its first week it overturned 23 of 83 proposals. A page that showed only the assessor would have shown a 28% false-positive rate as a to-do list.

Each finding carries a verdict, a disposition, a severity, what was expected, the evidence, the components involved, and whether it is a regression. Findings and their transcripts expire together on a configurable horizon. A companion report lists every confirmed finding whose suggested regression test does not yet exist, so the backlog is a number that can reach zero rather than one that drifts.

There is an experimental automatic fixer, and it is off by default because it did not work: of 84 proposed defects, the challenger rejected 23, 48 of the remaining 59 failed the full gate across 81 distinct broken tests, 10 of the 11 survivors were rejected by the final reviewer, and the single approved patch failed to install. Nothing landed. That outcome is recorded rather than quietly deleted, which is the same standard the product holds itself to everywhere else.

The review ledger

Separate from findings, a daily pass reviews how individual episodes ended. Its ledger carries two independent flags rather than one status, because an episode whose ending moved after it was reviewed is simultaneously reviewed — of an ending that no longer exists — and awaiting review. Collapsing those into one state would lose the only interesting case. Work still running is neither.

Audit

The audit page answers who did what, and what came of it. Denied and privileged actions, correction events, memory reviews, publications, discards.

One detail is a good example of the house style: the actor column names a kind — a person, an app, the host, this dashboard — beside the raw Slack ID. There is no user directory, and inventing a display name would be worse than showing the ID.

Audit runs on its own retention horizon, which is never shorter than the episode horizon and can be configured far longer. Forgotten memory values are not copied into audit state; only the entry ID, scope, predicate, actor and outcome are kept, with replacement history stored as hashes.

Failures and workspaces

The Failures page lists terminal work with its retained error and whether it can be retried. A retry puts the run back to pending with a fresh Coop idempotency key and reopens its episode. Only the latest attempt qualifies — a superseded run names the attempt that replaced it instead of offering a button the store would refuse.

The Workspaces page mirrors the Slack admission gate exactly: publish and discard call the identical service handlers the Slack buttons call, including the Coop review, the verified discard plan, the audit record and the Slack notice. Closed work refuses to publish here too. A session with no work record says plainly that no safe discard path exists for it yet, rather than inventing one.

What it will not become

  • Multiple users, accounts, or roles.
  • Editing prompts or policies in the browser. Those are code and config, reviewed in git.
  • Anything that mutates infrastructure. Emisar remains the only path.
  • A replacement for the Slack App Home.
  • Public exposure. Binding it even to a private network was considered and rejected: tagged service devices would then reach production episode content, evidence, and prompts.

One last detail that tells you what kind of surface this is: the schema version it shows is read from the database, not from a constant in the binary — so the page reports the schema actually in use rather than the one this build expects. Those differ exactly when something is wrong.
